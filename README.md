# PODOLOGY MK | Марина Кандыкбаева

Многостраничный сайт услуг в Актобе и профессионального обучения по Казахстану. RU / KK, 54 страницы в стартовой сборке, шаблоны услуг, курсов, специалистов, филиалов, событий, отзывов, статей и случаев. Данные находятся в `content/site.json`.

**Текущий статус: предварительная версия с графическими заглушками.** Фотографии, сведения об образовании, документы об окончании, прайс и даты не выдуманы. Подтверждённые предложения конкретных специалистов пока отсутствуют. ФДТ, уход при диабете, выезд на дом и другие неподтверждённые услуги имеют `published: false` и отсутствуют в каталоге и sitemap. Индексация всего предварительного сайта закрыта настройкой `settings.indexable: false`.

## Локальный запуск

Требуется Node.js 24. Для статической сборки внешние зависимости не нужны.

```sh
npm test
npm run build
npm run preview
```

Сайт: `http://localhost:4173/ru`. Редактор: `http://localhost:4173/admin`.

## Два варианта размещения

| Возможность | Статический хостинг / GitHub Pages / Sites | Cloudflare Worker + D1 |
| --- | --- | --- |
| Все публичные страницы, RU/KK | Да | Да |
| Изменение контента | Редактор → экспорт JSON → пересборка | Защищённая CMS → сразу на сайте |
| Формы | Подготовка сообщения в WhatsApp | WhatsApp или запись в D1 с Turnstile |
| Статусы, нормализация URL, история slug | Ограничения статического хостинга | 200 / 301 / 404 / 500, постоянные редиректы |
| Личный кабинет учащегося, видеоуроки, платежи | Не входят в эту версию | Не входят в эту версию |

Не называть открытие WhatsApp отправленной заявкой: события `whatsapp_form_open` и `generate_lead` разделены. Пользователь должен сам отправить сообщение. Форма не загружает фото и не запрашивает подробные медицинские данные.

## GitHub

Репозиторий: https://github.com/kandykbayevtagir-wq/podology

Workflow `.github/workflows/pages.yml` проверяет и собирает сайт, затем включает GitHub Pages и публикует его через Actions. Целевой URL: `https://kandykbayevtagir-wq.github.io/podology/`. Настройка учитывает базовый путь `/podology`.

Если GitHub не разрешает автоматическое включение Pages, владельцу нужно выбрать Settings → Pages → Source: **GitHub Actions**, затем повторить workflow. В текущем окружении вызовы Pages API от интеграции возвращают 403. Для приватного репозитория возможность Pages зависит также от тарифа аккаунта. Видимость репозитория автоматически не меняется.

Дополнительно в ветку `gh-pages` подготовлена собранная статическая версия. Её можно публиковать через Settings → Pages → Deploy from a branch → gh-pages → /(root). Исходники остаются в main.

GitHub Pages не выполняет Worker: редактор сохраняет через экспорт JSON, формы работают через WhatsApp. Для собственного домена измените SITE_ORIGIN и BASE_PATH в workflow, затем настройте домен в Pages.

## Cloudflare — полный режим CMS

Развёртывание в собственном аккаунте Cloudflare в текущем окружении не выполнено: Cloudflare API credentials отсутствуют.

1. Установите зависимости `npm ci` и авторизуйте Wrangler в своём аккаунте.
2. Создайте базу: `npx wrangler d1 create podology-mk-content`.
3. Вставьте возвращённый `database_id` в `wrangler.jsonc`. Не используйте идентификатор-заглушку.
4. Выполните `npx wrangler d1 migrations apply podology-mk-content --remote`.
5. Задайте фактический HTTPS-адрес сайта в `settings.origin` файла контента.
6. Выполните `npm run deploy:cloudflare`.
7. Запустите `node scripts/set-admin-password.mjs`: пароль вводится скрыто, PBKDF2-хеш и случайный ключ сессии передаются в Wrangler через stdin. Никакие секреты не сохраняются в проекте.
8. Откройте `/admin`, войдите и редактируйте контент. Данные хранятся в D1 и видны на публичных страницах без пересборки. Сохранения защищены от конфликта версий. Новые slug опубликованных сущностей получают 301 со старого адреса.

Автоматизация Cloudflare: workflow `cloudflare.yml` запускается вручную. Нужны repository secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, repository variable `D1_DATABASE_ID`. Токену нужны Workers Scripts Edit и D1 Edit в нужном аккаунте. Подключите собственный домен в Workers → Settings → Domains & Routes. HTTPS выдаётся Cloudflare.

### Серверные заявки

По умолчанию `bookingMode: whatsapp`. Для включения серверной формы:

- Утвердите юридические реквизиты, редакцию согласия, получателей и срок хранения персональных данных. Сейчас юридические страницы помечены предварительными.
- Создайте Turnstile widget для фактического домена. Запишите его публичный ключ в `settings.turnstileSiteKey`, секрет — через `npx wrangler secret put TURNSTILE_SECRET`.
- Переключите `settings.bookingMode` на `server` в CMS. Без D1 и настроенного Turnstile API отклонит заявку.
- Проверяйте раздел «Заявки» в `/admin`. В этой версии не настроены автоматические уведомления по почте, CRM или мессенджерам; заявки читаются в панели.
- Настройте регламент удаления заявок. Панель позволяет удалять их индивидуально. Автоматическое удаление по срокам не включено до утверждения срока хранения.

Антиспам: Turnstile с проверкой домена, honeypot, время заполнения, лимиты по IP (в базе хранится HMAC, а не исходный IP), ограничения размеров и типов. Админ-сессии: HMAC, HttpOnly / Secure / SameSite cookie, 8 часов, PBKDF2 100000 итераций, ограничение попыток и проверка Origin. Админ-пароль и ключ сессии — только secrets Cloudflare.

## Контент и фотографии

`/admin` содержит формы RU / KK, редактор исходного JSON и экспорт/импорт. В статическом режиме файл экспортируется как `site.json`; замените `content/site.json`, выполните тесты, сборку и публикацию. Импорт в браузер не означает публикацию.

Фото добавляются в `public/assets/`, затем меняется поле `image` соответствующей сущности. Заглушки — собственные SVG, сторонние фотографии не использовались. Для портрета Марины: `specialists[0].image`. Hero сейчас задаётся в `src/render.mjs` как `/assets/hero.svg`; замените путь на оптимизированную реальную фотографию. Форматы: WebP / AVIF, без EXIF; желательно несколько размеров при финальной обработке.

Не добавляйте отзывы без источников и согласий, фотографии случаев — без согласий. Разделы «Статьи», «Случаи», «Отзывы» и «Семинары» пока честно показывают отсутствие утверждённого материала. Новые записи создаются как черновики. Курсам оставлены предварительные темы из ТЗ; часы, даты, цены и документы требуют утверждения. Казахский перевод — предварительный, нужна редактура носителем языка.

### Цены

Модель `offerings`: `serviceId × specialistId × locationId`, `price`, `currency: KZT`, `priceType: fixed | from | consultation`, `durationMinutes`, `isAvailable`, `bookingEnabled`, `notes`, `updatedAt`. Вёрстка показывает только существующие опубликованные связи. Нет условных цен или выдуманных специалистов. Пример структуры — в `docs/content-model.md`.

## SEO и аналитика

- Один H1, Title, Description, canonical, RU/KK hreflang, sitemap.xml, robots.txt, schema.org Organization / LocalBusiness / Course / BreadcrumbList.
- В предварительной версии индексация закрыта. После подготовки контента включите `settings.indexable` и отключите `preview`. Неподтверждённые услуги должны оставаться черновиками.
- `settings.googleVerification` — значение проверки Search Console. Добавьте ресурс в своём аккаунте, подтвердите домен/URL и отправьте sitemap. Само создание ресурса через аккаунт Google не выполнено.
- `settings.ga4Id`, `adsId`, `adsLeadLabel`, `adsWhatsappLabel` — реальные идентификаторы из ваших аккаунтов. Без них сторонние теги не загружаются. Consent banner включает их только после согласия. Отказ прекращает сбор и перезагружает страницу при уже загруженном теге. Имена, телефоны и комментарии в аналитику не передаются.
- События: `phone_click`, `directions_click`, `whatsapp_click`, `whatsapp_form_open`, `generate_lead` (только подтверждённая сервером запись). UTM/gclid/gbraid/wbraid сохраняются в sessionStorage вкладки и передаются с запросом.
- Организация рекламных кампаний и их импортные заготовки: `docs/ads-plan.md`. Кампании не запущены, бюджет не расходуется.
